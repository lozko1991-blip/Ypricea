# UTRADE — інструкція з налаштування

Сервіс автоматично кожні **5 годин** завантажує великий XML-прайс постачальника, фільтрує його, складає в **один JSON-файл** (`allyavdata.json`) і публікує сайт-каталог **UTRADE** з вбудованим **генератором прайсу для Prom.ua** та блоком автопрайсів. Сайт читає всі дані з цього одного файлу.

Адреса сайту після налаштування: **https://lozko1991-blip.github.io/Ypricea/**

---

## 1. Як це працює (коротко)

```
Кожні 5 год:  GitHub Actions  →  fetch XML  →  фільтр  →  один JSON  →  deploy на Pages
Сайт:         браузер читає data/allyavdata.json  (категорії + усі товари, без важкого XML)
Генератор:    обираєш категорії + націнку → формуєш Prom XML → завантажуєш
```

Дані складаються в **один файл** `data/allyavdata.json` (структура повторює XML постачальника: ті самі поля offer/category, нічого по суті не перейменовується). Поруч кладеться його стиснута копія `data/allyavdata.min.json.gz` — для зовнішніх проектів чи ручного завантаження. Сирий XML на GitHub не зберігається — він існує лише всередині Actions під час обробки. Деплой іде через артефакт Pages, без комітів даних у репозиторій.

> Увага щодо лімітів: якщо `allyavdata.json` колись перевалить за ~100 МБ, його все одно можна публікувати через Pages (там ліміт на артефакт значно більший), але варто стежити за розміром. Браузер при завантаженні з Pages отримує файл уже gzip-стиснутим автоматично.

## 2. Правила обробки (вже зашиті в код)

1. Товари з **ціною постачальника < 200 грн** видаляються (закупівельна ціна береться з тегу `<price>`).
2. Ціна продажу: **`ціна = закупівля × 1.20 + 70 грн`** (округлення до цілого). Напр. 352 → 492, 584 → 771.
3. Рахуємо товари по **листових** категоріях; листову з **4 і менше** товарів видаляємо разом з товарами.
4. Порожні батьківські категорії (без жодного товару в піддереві) видаляються.
5. Зберігаються **обидві мови** (назва + опис RU та UA), усі фото, параметри, `group_id`, штрихкод. Опис, що в прайсі стоїть лише на одному товарі групи `group_id`, **розмножується на всі варіанти** групи.
6. Валюта вигрузки — **UAH**.

Усі ці значення легко змінити вгорі файлу `scripts/process.mjs` (блок `CONFIG`).

## 3. Створення репозиторію (один раз)

1. Зайди на свій GitHub: **https://github.com/lozko1991-blip**
2. Натисни **New repository**, назва репозиторію — `Ypricea`, тип — **Public** (публічний, щоб Actions і Pages були безкоштовні).
3. Завантаж у репозиторій таку структуру файлів:

```
Ypricea/
├── index.html                     ← сторінка-каталог + генератор
├── package.json
├── scripts/
│   └── process.mjs                ← обробка прайсу (Node.js)
├── presets/                       ← рецепти автопрайсів (export-1.json і т.д.)
└── .github/
    └── workflows/
        └── update.yml             ← розклад кожні 5 годин + публікація
```

> Теку `presets/` можна спершу не створювати — без неї все працює, просто не буде автопрайсів. Вона зʼявиться сама, коли покладеш перший рецепт (розділ 8).

Файли `index.html`, `package.json`, `scripts/process.mjs`, `.github/workflows/update.yml` я надав окремо — просто поклади їх за цими шляхами.

---

## 4. Увімкнення GitHub Pages

1. У репозиторії: **Settings → Pages**.
2. У полі **Source** обери **GitHub Actions** (не «Deploy from a branch»).
3. Збережи. Більше тут нічого не треба — публікацією керує наш workflow.

---

## 5. Перший запуск

1. Відкрий вкладку **Actions** у репозиторії.
2. Зліва обери workflow **Update price catalog**.
3. Натисни **Run workflow** → **Run workflow** (ручний запуск).
4. Зачекай 3–8 хвилин. Коли запуск стане зеленим — сайт опубліковано.
5. Відкрий **https://lozko1991-blip.github.io/Ypricea/**

Далі він оновлюватиметься **сам кожні 5 годин** (за UTC: о 00:00, 05:00, 10:00, 15:00, 20:00; на безкоштовному плані можлива затримка на кілька хвилин).

## 6. Звіт і статистика помилок

Після кожного запуску дивись звіт у **трьох місцях**:

- **Actions → останній запуск → Summary** — короткий звіт прямо на сторінці запуску: скільки скачано, скільки відсіяно по ціні, скільки категорій видалено (малі/порожні), фінальна кількість, попередження.
- **https://lozko1991-blip.github.io/Ypricea/data/report.json** — той самий звіт у JSON.
- На самому сайті у блоці **«Про нас»** (кнопка ℹ️ у шапці) показується час останнього оновлення, кількість товарів і контакти.

## 7. Як користуватись генератором прайсу

1. На сайті прокрути до секції **«Генератор прайсу для Prom.ua»** (внизу).
2. Постав галочки на потрібних категоріях (галочка на батьківській обирає всі дочірні; біля кожної — кількість товарів).
3. Вкажи: **націнку %**, **націнку грн**, **мінімальну ціну** (drop), за бажанням — «тільки наявні».
4. Побачиш лічильник: **скільки категорій і товарів** потрапить у вигрузку.
5. Натисни **«Згенерувати Prom XML»** — файл завантажиться. Його можна імпортувати в Prom.ua.
6. Кнопка **«Скопіювати посилання-рецепт»** дає посилання з твоїми налаштуваннями — відкривши його, побачиш ті самі категорії й націнку вже виставленими.

> Зараз генерація відбувається **миттєво в браузері** (Етап 1). Дані під нею оновлюються кожні 5 годин, тож вигрузка завжди зі свіжих цін і наявності.

## 8. Автопрайс — щоб Prom оновлював товари сам

Браузерний генератор (розділ 7) робить файл лише тоді, коли ти сам натискаєш кнопку. Щоб **Prom.ua оновлював товари за розкладом без тебе**, потрібен готовий XML за постійним посиланням, який сервер перегенеровує сам. Це і є автопрайс.

Як налаштувати (один раз на кожен набір категорій):

1. На сайті у секції генератора познач потрібні категорії і вкажи націнку.
2. Натисни **«Зберегти як автопрайс»**. Відкриється вікно з готовим вмістом файлу-рецепта.
3. За потреби зміни назву (за нею буде названо файл і посилання). За замовчуванням `export-1`.
4. Поклади цей файл у репозиторій за шляхом **`presets/export-1.json`**. Найшвидше — кнопкою у вікні **«GitHub → Create new file»**: встав назву `presets/export-1.json` і вміст, тоді **Commit**.
5. Дочекайся наступного запуску (або Actions → **Run workflow**).

Готово. Тепер за постійним посиланням завжди лежить свіжий прайс:

```
https://lozko1991-blip.github.io/Ypricea/exports/export-1.xml
```

Саме це посилання вставляєш у Prom.ua (Налаштування імпорту → за посиланням) **або** на будь-який інший сайт-майданчик. Після першого запуску на самому сайті (над генератором) зʼявиться блок **«Мої автопрайси»** з усіма твоїми експортами, їх постійними посиланнями та кнопками «Копіювати»/«Відкрити». Ланцюжок далі працює сам:

```
постачальник оновив ціни/наявність
  → Actions (кожні 5 год) качає й перераховує
  → перезаписує exports/export-1.xml зі свіжими даними
  → Prom за своїм розкладом забирає файл за посиланням
  → товари оновились
```

Кілька прайсів одночасно: створи кілька рецептів — `presets/export-1.json`, `presets/export-2.json` тощо (різні назви). Кожен дасть свій файл: `exports/export-1.xml`, `exports/export-2.xml`. Зручно під різні майданчики чи набори категорій.

Зміна вибірки: відкрий той самий рецепт у генераторі, перезбережи з **тією ж назвою** і заміни вміст файлу в репозиторії — посилання лишиться те саме, оновиться вміст.

> Націнка в автопрайсі береться **з пресету** (та, що ти виставив при збереженні), незалежно від загальних правил бази. Поріг мінімальної ціни й «тільки наявні» — теж із пресету.

## 9. Якщо щось не працює

- **Actions падає на кроці завантаження XML** — перевір, чи доступний `https://crm.yavshoke.ua/media/export/all_drop_opt_price.xml` (може бути тимчасово недоступний або змінив адресу). Адреса задається вгорі `process.mjs`.
- **Сайт порожній / 404** — переконайся, що в Settings → Pages джерело = **GitHub Actions**, і що перший запуск завершився зелено.
- **Замало памʼяті при обробці** — у `update.yml` вже стоїть `NODE_OPTIONS=--max-old-space-size=6144`. Якщо прайс дуже виросте, підніми значення.
- **Помилки в окремих товарах** — не валять увесь прайс; вони потрапляють у `report.json` як `warnings`.
